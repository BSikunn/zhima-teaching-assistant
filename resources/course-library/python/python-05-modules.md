# 模块拆分、导入与入口保护

课程：Python｜讲义编号：python-05-modules｜整理日期：2026-10-31

## 实验情境与目标

当一个成绩工具超过几十行，规则函数、命令行输出和示例数据应该逐步拆开。模块拆分的价值是让其他程序能复用计算规则，同时不会因为导入模块就突然读取用户输入、写文件或打印整份报告。本实验创建两个文件并验证这条边界。

## 概念与设计步骤

一个 Python 文件可以作为模块被导入，也可以直接作为脚本运行。把可复用函数放在模块顶层，把交互行为放在 main 中，并使用 __name__ 判断是否执行入口。导入时顶层语句仍会执行，因此入口保护不是忽略所有副作用的魔法；网络访问、大文件读取和连接数据库同样不应随意出现在导入路径上。

## 可运行示例

运行环境：Python 3.12；仅使用标准库；在独立练习目录运行，避免覆盖已有文件。

```python
# 文件 grade_rules.py
def is_passed(score, pass_line=60):
    return score >= pass_line

def main():
    print("规则模块自检：", is_passed(60))

if __name__ == "__main__":
    main()

```

## 逐步验证与结果解释

在同一目录另建 report.py，写入 from grade_rules import is_passed，再写 print(is_passed(59))。执行 python report.py 时只应输出 False，不出现规则模块的自检文字；执行 python grade_rules.py 时则出现自检输出。两个命令的区别说明，同一个文件的复用接口与直接运行入口可以清晰分开。

## 常见误区

不要把文件命名为 json.py、random.py 或与现有依赖同名，否则可能遮住标准库。避免 from module import *，它让名字来源难追踪。循环导入往往意味着模块职责没有拆清，可以把共享的数据定义移动到更基础的模块，而不是在各处反复尝试导入。

验收要求导入计算模块时不产生交互输出，正常调用能得到正确判定。提交中写清项目工作目录与运行命令，避免只在编辑器里通过某个隐含搜索路径运行成功，却无法让同学在终端重现。
