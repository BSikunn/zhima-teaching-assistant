# 连接查询与一对多行数

课程：数据库｜讲义编号：mysql-04-joins｜整理日期：2026-10-31

## 实验情境与目标

查询学生及其选课名称时，无选课学生也必须出现在名单中。这就是内连接与左连接会导致不同业务结果的典型场景。本讲义把三个学生和三条选课记录摆在一起，逐行判断匹配关系；行数变化本身也是验证连接条件的重要证据。

## 概念与设计步骤

把学生表作为左侧，选课表作为右侧，匹配条件是两边学生编号相等。学生有两条选课时，连接结果产生两行，这是关系的一对多展开，并非数据库凭空复制。没有匹配记录时，左连接仍保留学生一行，右侧字段为空。查询结果到底希望一人一行还是一条选课一行，需要在写 SQL 之前决定。

## 可运行示例

运行环境：MySQL 8.0。建表型实验只在专用 library_lab 库运行；已有数据先备份，避免与其他作业表混用。

```sql
WITH students AS (
 SELECT 1 AS id,'小禾' AS name
 UNION ALL SELECT 2,'小雨'
 UNION ALL SELECT 3,'小川'
), enrollments AS (
 SELECT 1 AS sid,'数据库' AS course
 UNION ALL SELECT 1,'Python'
 UNION ALL SELECT 2,'Java'
)
SELECT s.id,s.name,e.course
FROM students AS s
LEFT JOIN enrollments AS e ON e.sid=s.id
ORDER BY s.id,e.course;
```

## 逐步验证与结果解释

结果共四行：小禾两行、小雨一行、小川一行且课程为空。改用 INNER JOIN 后会变成三行，小川消失。若随后在 WHERE 写 e.course='Java'，空值行也被过滤掉，因此不能声称这种写法仍保留全部学生。希望保留全体学生且只展示匹配的 Java 选课时，应把右表课程条件放在 ON 中。

## 常见误区

漏掉 ON 条件会得到交叉组合；连错编号可能得到看似合理但属于他人的课程。连接后 COUNT(*) 会把没有选课学生的保留行也算进去，统计选课数时应计数右侧非空的键。无依据地加 DISTINCT 会遮住错误匹配，应先解释每一行的来源。

## 练习

分别写出没有选课的学生名单、每名学生的选课门数和选了 Java 的学生名单。再加入一条小雨的数据库选课，预测原左连接行数以及两人的选课数量，然后执行核对。

## 验收要点与思路

没有选课者只有小川；初始门数依次是二、一、零。新增后连接共五行，小雨门数变成二。答案需要同时交代连接类型、连接条件和统计字段，三个部分缺一不可。
