# 从业务对象设计关系表

课程：数据库｜讲义编号：mysql-01-schema｜整理日期：2026-10-31

## 实验情境与目标

选课系统最容易混淆的是学生与选课记录。学生信息描述一个人，选课记录描述这个人与某门课程发生的关系。如果把多门课程塞进一个以逗号分隔的字段，就很难给某门课程添加独立的成绩，也很难检查课程编号是否存在。本实验把一张表的每一行代表什么先写清楚，再决定主键与字段。

## 概念与设计步骤

建表前先写出三个问题：一行表示什么、怎样唯一识别、哪些值必须提供。学生编号采用整数主键，姓名只是展示属性，不承担唯一身份。金额或精确小数需要考虑 DECIMAL，文字长度根据业务范围选择，不能因为示例数据短就推断真实数据永远短。数据库字符集使用 utf8mb4，使后续中文及补充字符的数据不受单字节假设限制。

## 可运行示例

运行环境：MySQL 8.0。建表型实验只在专用 library_lab 库运行；已有数据先备份，避免与其他作业表混用。

```sql
CREATE DATABASE IF NOT EXISTS library_lab CHARACTER SET utf8mb4;
USE library_lab;
CREATE TABLE IF NOT EXISTS lab_student (
  id INT PRIMARY KEY,
  name VARCHAR(40) NOT NULL,
  class_name VARCHAR(40) NOT NULL,
  entry_year SMALLINT NOT NULL
) ENGINE=InnoDB;
INSERT INTO lab_student VALUES
 (101,'小禾','软件一班',2026),(102,'小雨','软件一班',2026);
DESCRIBE lab_student;
SELECT id,name FROM lab_student ORDER BY id;
```

## 逐步验证与结果解释

最后两行查询应显示两个学生，编号依次为一百零一和一百零二。DESCRIBE 用来核对字段、空值规则和主键信息，不代替业务验证。首次运行后再执行插入会触发重复主键错误，这正说明主键在保护身份唯一性；练习时应改用新的编号，或者在独立练习库中显式清理自己创建的数据。

## 常见误区

把姓名当主键会在同名学生出现时失败；用自动递增编号也不意味着编号连续或可以表示人数。NOT NULL 只拒绝空值，不能自动拒绝空字符串。CREATE TABLE IF NOT EXISTS 不会自动把旧表改成新结构，因此实验已有同名表时还要检查实际定义。

## 练习

设计一个教材表，保存教材编号、名称、价格、出版年份；说明价格为什么不直接使用浮点数。再设计一条选课记录的字段清单，指出哪些字段应引用学生与课程，而不是复制所有文字描述。

## 验收要点与思路

验收时要求主键重复能被拒绝，中文教材名能够往返读取，未填必填字段时有明确错误。解释身份字段与展示字段的区别，比把建表语句背下来更重要。
