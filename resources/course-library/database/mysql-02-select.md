# 筛选、排序与空值的查询推理

课程：数据库｜讲义编号：mysql-02-select｜整理日期：2026-10-31

## 实验情境与目标

班主任需要找到已经登记成绩且达到优秀线的学生，同时希望同分时名单顺序稳定。这听起来只是筛选，但实际同时涉及条件含义、空值和排序。先在纸上判断每行是否满足条件，再用数据库核对，能避免把碰巧正确的结果误认为正确规则。

## 概念与设计步骤

本实验用派生出来的临时样本，不依赖其他讲义的建表步骤。查询从数据行出发，WHERE 决定哪些行留下，SELECT 决定展示哪些字段，ORDER BY 决定结果顺序。NULL 在这里表示尚未登记成绩，因此未登记与零分是两种不同业务状态；是否计入统计必须由业务明确定义，不能随手把两者混为一谈。

## 可运行示例

运行环境：MySQL 8.0。建表型实验只在专用 library_lab 库运行；已有数据先备份，避免与其他作业表混用。

```sql
WITH marks AS (
 SELECT 11 AS id,'小禾' AS name,92 AS score
 UNION ALL SELECT 12,'小雨',NULL
 UNION ALL SELECT 13,'小川',92
 UNION ALL SELECT 14,'小夏',58
)
SELECT id,name,score
FROM marks
WHERE score IS NOT NULL AND score >= 90
ORDER BY score DESC,id ASC
LIMIT 10;
```

## 逐步验证与结果解释

应得到小禾与小川两行，且编号较小的小禾在前。把优秀线改为六十分，小夏仍不会进入结果；把条件改为 score IS NULL，则只会得到小雨。把排序中的编号删除后，同分者之间的相对位置没有稳定约定，分页时容易看到同一条记录出现在不同页。

## 常见误区

不要用等号与 NULL 比较来判断未登记。不要把 SELECT 的书写顺序误当作数据库必然采用的物理执行顺序。LIKE 匹配中的通配符也不是正则表达式语法。日期筛选建议明确区间边界，例如从某日开始且在次月一日之前，减少时间部分造成的漏查。

## 练习

加入一个成绩为零的学生，分别查询未登记、未及格、优秀三类名单；预测每类人数再执行。设计按成绩降序、姓名升序、编号升序排列的表达式，说明为什么最后仍保留编号。

## 验收要点与思路

提交三条查询及各自结果，并用一句话解释零分与未知分数的差别。若名单顺序影响分页，验收数据必须至少包含两个同分学生，不能只拿每个人成绩都不同的样本证明排序正确。
