# 智码助教

面向编程教学的课程智能体，包含知识库、带引用问答、作业批改与教师复核、错题本、复习计划、模拟测验、逐轮面试、学习与教学报告。

课程固定为数据库、Python、Java；学生为张三、李四、王五，教师为 T老师。每门课程都有讲义、至少三份练习和评分标准。本次又为每课补充10份中文主题讲义，共30份，包含示例、误区、练习和官方资料来源。

## 功能

- 教师上传 PDF/PPTX/DOCX/TXT/MD/SRT/VTT，单文件20MB；按实际页、段落、表格和字幕时间位置解析。扫描PDF无文本时明确报错。
- LlamaIndex SentenceSplitter 切片，BGE 中文向量和 Chroma 检索，Workflow 执行意图识别、检索、生成、引用校验及学情记录。SQL重验课程与资料状态，删除资料后立即排除新问答。
- 真实 DeepSeek 问答、建议批改、题目生成、测验评分、报告生成；课程问题应用教师教学设置，通用问题正常回答。建议分支持教师复核，代码未执行时如实标明。
- 问答优先参考本课程资料，可通过“联网补充”取得实际网页搜索摘要后生成。课程无关、资料不足、索引或搜索失败时，继续调用模型自身知识回答；课程资料、网页和模型知识分别标注。搜索结果有网络/限流影响，不把模型知识冒称联网成功；网页引用可查看当时摘要及打开原链接。
- 提交request_id幂等，模型调用前原子领取任务，重复worker投递不重复付费、不覆盖教师复核。当前本机与生产方案均使用Celery异步；隔离测试与演示仍可选择eager执行器。
- 测验作答前隐藏答案，面试逐轮展示与反馈；学生仅访问本人记录，教师范围由课程鉴权校验。
- 错题与复习计划按课程生成；SQL/Pandas汇总真实记录，排除历史演示种子。报告区分客观数据与AI建议，受保护接口下载UTF-8 Markdown。
- 管理员探测实际服务并展示时间，配置存在不代表连接成功。
- Judge0已接通官方实例，读取实际语言并限制执行时长、内存、输出和网络；Python/Java/SQL真实执行通过。代码与标准输入发送至远程沙箱，SQL实例为SQLite，MySQL专有语法不保证兼容；不在宿主机运行学生代码。

已安装faster-whisper依赖；原始音视频转写、语音问答、多智能体未纳入已验收功能。视频字幕可直接上传。

## 依赖和配置

新下载全部位于项目：Python包在 `.venv/`，前端包在 `frontend/node_modules/`，缓存与临时文件在 `.cache/`，模型在 `models/bge-small-zh-v1.5/`。下载器固定官方模型版本并验证权重SHA-256。`requirements-local.lock.txt`记录本次Windows环境；容器使用`requirements-prod.txt`。

```powershell
. .\scripts\env.ps1
.\.venv\Scripts\python.exe scripts/download-models.py
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

`env.ps1`将pip、npm、Hugging Face、Torch、NLTK、tiktoken、Playwright及临时目录指向项目。安装脚本可用`-Python '已有解释器绝对路径'`指定Python3.11/3.12。

`.env.example`是不带密钥的示例。私有`.env`主要变量：AI_MODE、DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_MODEL、TASK_MODE、STORAGE_BACKEND、RETRIEVAL_BACKEND、INDEX_URL、INDEX_TOKEN。`AI_MODE=demo`明确标注规则反馈，普通临时库测试强制demo/eager/local，不产生模型费用；无效模式拒绝启动。可选沙箱变量为JUDGE0_URL、JUDGE0_KEY。联网配置为WEB_SEARCH_ENABLED=true、WEB_SEARCH_PROVIDER=ddgs、WEB_SEARCH_BACKEND=yahoo、WEB_SEARCH_TIMEOUT=10、WEB_SEARCH_MAX_RESULTS=3；默认无需额外搜索Key，用户可在聊天中关闭联网。只向搜索引擎发送简短问题和相关课程标题，不发送整份课件或对话历史。

## 迁移与备份

先停止API/worker，再显式迁移；不要仅修改seed或手工删除旧账号。

```powershell
. .\scripts\env.ps1
.\scripts\stop.ps1
.\.venv\Scripts\python.exe -m app.migration --backup
.\.venv\Scripts\python.exe -m app.migration --upgrade
```

SQLite使用backup API生成一致性备份并检查完整性，然后归档移出名单账号的全部关联记录，保留指定账号ID、密码与合法历史，补齐课程，记录逐表数量并轮换JWT。重复执行不会重复迁移；旧令牌失效后重新登录。

备份在`.cache/backups/upgrade-20261029/`，包含数据库、上传资料、对象文件和必要私有配置。**备份含私有资料与凭据，勿提交或公开分享。** 回滚时停止服务，将所选备份的zhima.db、uploads、objects、.jwt-secret及.env恢复到原位置，并使用匹配代码；先在临时目录验证恢复。`--source <源库绝对路径>`可迁入DATABASE_URL指定的空库，源库保持只读，非空目标拒绝覆盖。

## 完整部署

`deploy/compose.yaml`含app、worker、index、mysql、redis、minio、nginx。数据、对象、索引、日志和备份绑定项目目录，仅Nginx的本机端口开放；BGE只读挂载，容器不自动下载模型。

```powershell
.\scripts\deploy.ps1 -Action check
.\scripts\deploy.ps1 -Action init
# 后续准备好Docker Linux容器环境，并核实镜像、构建缓存、VM/VHD位于项目内后：
$env:PROJECT_DOCKER_STORAGE_APPROVED='1'
.\scripts\deploy.ps1 -Action up
.\scripts\deploy.ps1 -Action status
.\scripts\backup.ps1 -Mode Compose
.\scripts\deploy.ps1 -Action migrate
.\scripts\deploy.ps1 -Action down
```

`init`从.env读取Key并生成数据库、MinIO、索引、JWT随机凭据到私有.env.compose，不打印密钥。存在本机SQLite时，首次up先备份并迁入空MySQL，再启动API/worker和同步索引，避免新库seed先写入。启动前先停止本机API，避免共用8765端口。源导入回执与目标数据在同一事务提交；中断后，同一路径且校验值相同的源库可以继续迁移，已完成的导入可重复执行。源库内容变化或无匹配回执的非空目标会拒绝覆盖。

MySQL升级先一致性mysqldump并备份文件，迁移通过`--backup-directory`验证COMPLETE、manifest及非空SQL；脚本将轮换的JWT同步到.env.compose。恢复Compose备份时，停止全部服务，在空MySQL中导入database.sql，再恢复container/chroma/redis/minio及私有.env.compose，先独立验证后恢复业务。

脚本不安装Docker/WSL，也不改变系统存储目录。YAML解析通过不等于容器集成通过，镜像拉取、MySQL/Redis/MinIO联通和worker跨进程流程仍需在可用Docker主机实测。

Worker异常退出后保留已领取任务状态，避免自动重放重复付费。停止所有worker并核对外部调用后，用`python -m app.jobs recover grade <提交ID> --workers-stopped`将指定未完成任务变为可重试状态，再恢复worker及从界面重试。也支持material、practice_generate、practice_grade、report。API重启不重置正常Celery任务。
